Участник организацииOrganisation member

Экосистема ассоциативного хранилища, где единственная сущность — связь: кортеж из идентификатора, типа и ссылок на другие связи. Одной таблицей описываются и данные, и схема, и обработчики.An ecosystem around associative storage where the only entity is a link: a tuple of an id, a type and references to other links. One table describes data, schema and handlers.

  • deep-files-sync (13 версий): проецирует граф связей на файловую систему, содержимое базы читается и правится через grep, редактор и git. Правки синхронизируются в обе стороны, удаление файла означает отписку.deep-files-sync (13 releases): projects the link graph onto the file system, so database content can be read and edited with grep, an editor and git. Edits sync both ways; deleting a file means unsubscribing.
  • Пакеты ИИ-тулинга в официальном скоупе: @deep-foundation/ai, ai-models, ai-templates, ai-tasks, 4o-bot, chatgpt-azure-deep, function_generation, tests_generation. Такой пакет — не библиотека, а выгрузка настроенного графа связей, которая разворачивается в чужом инстансе.AI tooling packages in the official scope: @deep-foundation/ai, ai-models, ai-templates, ai-tasks, 4o-bot, chatgpt-azure-deep, function_generation, tests_generation. IXМетодMethod

  1. 1

    РамкаFrame

    Исследование, ограничения и критерии приёмки фиксирую сам, до того как подключаю модель.I fix the research, constraints and acceptance criteria myself before a model gets involved.

  2. 2

    ПравилаRules

    Перед работой записываю в репозиторий полный набор правил: как гонять проверки, чего не трогать. Те же ограничения дублирую в CI и хуках, чтобы их нельзя было обойти.Before any work I put a complete rule set into the repository: how to run checks, what not to touch. The same limits are duplicated in CI and hooks so they cannot be bypassed.

  3. 3

    Узкие шагиNarrow steps

    Код с моделью пишу узкими шагами и через отдельных субагентов: план, правка, прогон тестов и линтеров. Скоуп файлов фиксирую заранее, параллельные правки изолирую.I write code with a model in narrow steps and through separate subagents: plan, edit, tests and linters. The file scope is fixed in advance; parallel edits are isolated.

  4. 4

    Независимая проверкаIndependent review

    Проверка идёт отдельно и не принимает код, который только что написал исполнитель. Тесты, написанные моделью вместе с реализацией, доказательством не считаю: смотрю негативные и граничные случаи, секреты и зависимости. Без собственного ревью код не отдаю.Review runs separately and rejects code the executor has just written. Tests a model wrote together with the implementation are not proof: I check negative and edge cases, secrets and dependencies. Nothing leaves my hands without my own review.
